# Поиск статей справки Avito по вопросу пользователя

Задача: по вопросу пользователя вернуть до 10 статей справки, отсортированных по релевантности. По сути это поисковая часть RAG. Метрика MAP@10.

## Результат

Замеры на калибровочной выборке (500 запросов):

| Метод | MAP@10 |
|---|---|
| BM25 | 0.2694 |
| Эмбеддинги e5 | 0.1741 |
| BM25 + эмбеддинги (RRF) | **0.3031** |

Ответы для теста лежат в `answer.csv`.

## Как запустить

Данных задания в репозитории нет, их нужно положить в `Files/candidate_data/` (`articles.f`, `calibration.f`, `test.f`).

```bash
python -m venv .venv
.venv\Scripts\activate        # на Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
python solution.py            # или прогнать solution.ipynb
```

В первый раз скачиваются модели с Hugging Face, примерно 1.1 ГБ. Потом всё работает локально. Эмбеддинги статей кэшируются в `cache/`, так что повторный запуск быстрый. Считается на CPU, если есть GPU, он подхватится сам (`device="auto"`).

## Что сделал

Взял два поиска, которые ошибаются в разных местах, и объединил их.

BM25 (`rank_bm25`) ищет по совпадению слов. На справке, где много специфичных слов, он работает неплохо.

Эмбеддинги `intfloat/multilingual-e5-base` ищут по смыслу, поэтому находят перефразы и синонимы, которые BM25 пропускает. Для этой модели нужны префиксы `query:` и `passage:`.

Списки от двух методов объединяю через Reciprocal Rank Fusion: каждая статья получает `1 / (k + место в списке)` от каждого метода, баллы складываются. Удобно, что не надо приводить к одной шкале баллы BM25 и косинусную близость.

### Подготовка текста

- Статьи хранятся в HTML. Вытаскиваю из них текст через BeautifulSoup, убираю скрипты, стили и лишние пробелы.
- Для BM25 беру заголовок два раза (чтобы он весил больше) и весь текст. Для эмбеддингов заголовок и начало статьи, потому что модель всё равно читает только ~512 токенов.
- Из запросов убираю плейсхолдеры вроде `<DATE>`.
- Для BM25: нижний регистр, стоп-слова, стемминг Snowball. Без стемминга «отправить» в вопросе не совпадает с «отправка» в статье.

### Что подбирал

Только общие параметры на калибровке, ничего под конкретные запросы:

- заголовок дублируется ×2;
- в стоп-слова добавил приветствия и вежливые фразы («здравствуйте, подскажите, пожалуйста»). Они есть почти в каждом вопросе и только мешают BM25. Дало +0.01–0.02;
- в RRF вес BM25 к эмбеддингам 2:1, потому что эмбеддинги здесь слабее.

### Реранкер

Пробовал добавить cross-encoder, который пересортирует топ кандидатов:

- `DiTy/cross-encoder-russian-msmarco` сделал хуже: 0.198 против 0.278 у гибрида в том же замере. Видимо, он обучен на переведённом MS MARCO и плохо понимает разговорные вопросы в поддержку.
- `BAAI/bge-reranker-v2-m3` дал +0.012, это в пределах шума, и работал около 34 секунд на запрос. На весь тест это часы.

В итоге отказался, но в коде оставил (`method="rerank"`).

## Разбор ошибок

Эмбеддинги отдельно оказались хуже BM25 (0.17 против 0.27), но вместе с ним дают 0.30, то есть находят то, что BM25 пропускает.

Посмотрел recall: правильная статья есть в топ-50 в 86% случаев, а в топ-10 только в 56%. Поиск её находит, но не поднимает наверх, потому что рядом стоят очень похожие статьи, например «Отправить заказ» и «Заказать товар с доставкой». Как раз на этом не справился реранкер.

## Файлы

- `pipeline.py` — вся логика: очистка, BM25, эмбеддинги, RRF, реранкер, метрика
- `solution.py` — запуск одной командой, создаёт `answer.csv`
- `solution.ipynb` — то же самое по шагам, с метриками
- `requirements.txt` — версии библиотек

## Воспроизводимость и ограничения задания

Сиды зафиксированы, версии библиотек закреплены, повторный запуск даёт тот же `answer.csv` (проверял сравнением файлов).

Внешние API и LLM не используются. Все модели меньше 1B параметров (e5-base около 278M). Ответы под конкретные запросы не подгонялись.

## Что можно улучшить

- попробовать модели посильнее для русского: e5-large, bge-m3;
- резать длинные статьи на куски, а не брать только начало;
- дообучить реранкер, чтобы он различал похожие статьи.
